# Скрипты сбора и обработки данных

Проект собран как **линейный пайплайн из независимых скриптов**: каждый скрипт решает одну задачу,
читает файлы предыдущего слоя и пишет свои. Оркестратора нет — скрипты запускаются по порядку
вручную (см. «Порядок запуска»). Промежуточные результаты сохраняются, повторный запуск использует
уже скачанные файлы, поэтому прерывание работы не приводит к потере данных.

Все зависимости (`numpy`, `python-docx`, `python-pptx`, `osmium`) лежат в локальной папке
`.tools` рабочего пространства и в систему не устанавливаются.

## Этапы проекта

| Этап | Скрипты | Задача этапа |
|---|---|---|
| 1. Сбор | `download_rosstat`, `get_region_boundary`, `download_osm_pbf`, `parse_vacancies_trudvsem` | получить данные из источников: сборник, границу области, выгрузку OSM, вакансии |
| 2. Парсинг | `rosstat_docx_to_text`, `rosstat_extract_region`, `parse_osm_objects`, `assign_cities` | превратить сырьё в таблицы и привязать объекты к территориям |
| 3. Анализ | `aggregate` | сводные таблицы и показатели |

Этапы связаны только через файлы: скрипт парсинга не знает, откуда взялся файл, а скрипт анализа —
как он был получен. Это позволяет перезапускать любой этап отдельно.

## Этап 1. Сбор

| Скрипт | Что делает | Вход → выход | Время |
|---|---|---|---|
| `download_rosstat.py` | Скачивает сборник «Регионы России — 2025» (.rar и .pdf) | сайт Росстата → `data/rosstat/*.rar` | ~1 мин |
| `get_region_boundary.py` | Получает полигон границы области (нужен для фильтрации объектов) | Nominatim → `data/osm/region_boundary.geojson` | ~5 с |
| `download_osm_pbf.py` | Скачивает выгрузку Приволжского федерального округа | Geofabrik → `data/osm/volga-fed-district-latest.osm.pbf` (0,77 ГБ) | ~3 мин |
| `parse_vacancies_trudvsem.py` | Собирает вакансии региона через API портала «Работа в России» | API → `data/labor/vacancies.csv`, `vacancies_raw.json` | ~5 мин |

**Ограничение API вакансий.** `offset + limit ≤ 200` на один запрос, фильтры по датам отвечают
HTTP 500. Поэтому перебор идёт не по страницам, а **по 129 ключевым словам профессий** (по 2 страницы
на слово) с параллельной обработкой в 5 потоков. Дедупликация — автоматическая: результаты
складываются в словарь по `id` вакансии.

## Этап 2. Парсинг

| Скрипт | Что делает | Вход → выход | Время |
|---|---|---|---|
| `rosstat_docx_to_text.py` | Распаковывает 22 раздела .docx и переводит каждый в текст: абзацы + все таблицы построчно | `.rar` → `data/rosstat/txt/R_*.txt` (823 таблицы) | ~1 мин |
| `rosstat_extract_region.py` | Ищет во всех разделах таблицы со строкой «Саратовская область» и сохраняет их | дампы → `saratov_tables.txt/.json` (397 таблиц) | ~10 с |
| `parse_osm_objects.py` | Разбирает PBF, отбирает объекты по тегам и фильтрует их по границе области | PBF + geojson → `data/osm/objects.csv/.json` | ~30 мин |
| `assign_cities.py` | Привязывает объекты к ближайшему городу области (в OSM поле города почти не заполнено) | `objects.csv` → `objects_by_city.csv` | ~1 мин |

**Особенность разбора сборника.** В «продолжениях» таблиц название региона стоит в **последней**
ячейке строки, а не в первой. Скрипт ищет регион по любой ячейке — иначе терялась бы часть
показателей, например структура ВРП по отраслям.

**Решения при разборе OSM:**
- **фильтр по полигону, а не по bbox** — иначе в выборку попадают объекты соседних регионов;
  проверка «точка внутри полигона» реализована лучевым методом и векторизована через `numpy`;
- отбор по тегам: `amenity=bank|atm`, `industrial=*`, `shop=supermarket|convenience|general`,
  `shop=beauty|hairdresser|massage`, `leisure=tanning_salon`;
- источник — выгрузка Geofabrik, а не Overpass API: Overpass сначала фильтровал запросы по
  User-Agent, затем не выдержал запрос по области и в итоге заблокировал IP.

## Этап 3. Анализ

| Скрипт | Что делает | Вход → выход | Время |
|---|---|---|---|
| `aggregate.py` | Разбирает все собранные файлы и считает сводные таблицы: топы профессий, сферы деятельности, зарплатную статистику, объекты по городам | `objects.csv`, `objects_by_city.csv`, `vacancies.csv` → таблицы в `analiz/` | секунды |

`aggregate.py` — единственный скрипт этапа анализа: он читает все три таблицы, полученные на этапах
сбора и парсинга, и не зависит от того, каким скриптом они созданы.

## Оформление результата (вне пайплайна)

Сборка презентации — не этап анализа, а оформление готовых таблиц: скрипт читает сводные данные
и собирает по ним слайды.

| Скрипт | Что делает | Вход → выход | Время |
|---|---|---|---|
| `make_presentation.py` | **Основной вариант:** презентация на официальном шаблоне СПбГУ — 19 слайдов, диаграммы, заметки докладчика | шаблон + сводные данные → `.pptx` | секунды |
| `make_presentation_plain.py` | Простой вариант без шаблона (собственная палитра) | сводные данные → `.pptx` | секунды |

Шаблон лежит вне проекта: `D:\spbu_diploma-master\ИИИВЭ\Новый вариант\Шаблон.pptx` (21 макет,
фирменные цвета, шрифты Open Sans). Скрипт удаляет демонстрационные слайды шаблона и строит свои
на его макетах, поэтому вся фирменная графика берётся из шаблона, а не рисуется заново.

Файлы фирменного стиля лежат в `../assets/`: `apple-touch-icon.png` — знак СПбГУ, `emblem-white.png` —
тот же знак без фона, `logo-big.svg` и `logo-text-smal.svg` — векторные версии с сайта вуза.

## Порядок запуска

```
python download_rosstat.py
python rosstat_docx_to_text.py
python rosstat_extract_region.py
python parse_vacancies_trudvsem.py
python get_region_boundary.py
python download_osm_pbf.py
python parse_osm_objects.py
python assign_cities.py
python aggregate.py
python make_presentation.py
```

Скрипты слоя 1 можно запускать в любом порядке, дальше — по зависимостям: `rosstat_*` после
`download_rosstat`, `parse_osm_objects` после `download_osm_pbf` и `get_region_boundary`,
`aggregate` после `parse_vacancies_trudvsem` и `assign_cities`.

## Чего в папке нет

- **Оркестратора** — запуск ручной, по списку выше. При необходимости его можно добавить,
  не меняя сами скрипты: слои связаны только через файлы.
- **Скриптов-разведчиков** (`probe_*.py`) и установщиков wheel-пакетов: это вспомогательный код,
  а не часть пайплайна. Их выводы зафиксированы в журнале `../data/README.md`.
- **Скриптов ранних версий презентации** — они сохранены в рабочем пространстве (`.tools`),
  но в проект не входят: актуальны только два варианта выше.
