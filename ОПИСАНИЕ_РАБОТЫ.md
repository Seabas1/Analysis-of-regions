# Анализ экономики Саратовской области: работа целиком

Единое описание проекта: задача, источники, сбор данных, аналитика по сферам, проверки,
ограничения и воспроизводимость. Документ сводит в одно место то, что раньше было разложено
по нескольким файлам: `README.md`, `Техническое_описание.md`, `Ход_работы.md`,
`Обзор_скриптов.md`, `00_План_и_структура.md`, `Разбор_*.md`, `data/README.md`,
`scripts/README.md`, `data/Саратов_сводка_показателей.md`.

**Итог работы:** собран полный набор открытых данных по региону — 476 таблиц сборника Росстата,
4 183 вакансии, 2 432 объекта экономики из OpenStreetMap; по ним посчитаны показатели трёх сфер
и построена презентация на официальном шаблоне СПбГУ (16 слайдов).

---

## 1. Задача и подход

**Задача.** Дать экономическое описание Саратовской области на основе открытых данных:
финансовый сектор, рынок труда, рынок товаров и услуг.

**Подход — инженерный, а не экономический.** Работа формализована как сбор и обработка данных,
а экономические выводы строятся уже на выверенных числах. Каждый показатель имеет источник
и скрипт, которым он получен. Требования, которые выполнялись:

- только открытые источники;
- воспроизводимость: каждый шаг — скрипт, порядок запуска описан;
- проверяемость: сверка независимых источников, фиксация ограничений, а не их сокрытие;
- минимум ручного труда: числа читаются из данных, а не переписываются в код.

**Формализация сущностей:**

| Сущность | Формализация | Источник |
|---|---|---|
| Объект экономики | `(тип, координаты, атрибуты)` | OpenStreetMap |
| Рабочее место | `(профессия, зарплата, работодатель, адрес)` | API «Работа в России» |
| Показатель региона | временной ряд `(год, значение, единица)` | Росстат / Банк России |
| Рынок | множество объектов + набор временных рядов | агрегация |

## 2. Источники данных

| Источник | Что берём | Формат | Объём |

| OpenStreetMap, выгрузка Geofabrik | объекты экономики: банки и банкоматы, производства, услуги, магазины | PBF, 739 МБ | 2 432 объекта |

Почему именно эти источники:

- **Росстат** — единственный официальный и полный источник региональных временных рядов;
- **trudvsem** — открытые микроданные о спросе на труд; обоснование взято из образца
  (данные онлайн-вакансий коррелируют с официальной статистикой);
- **OpenStreetMap** — единственный открытый источник с координатами объектов; статистика
  не отвечает на вопрос «где именно», OSM отвечает;
- **Nominatim** — справочная геометрия, без неё нельзя фильтровать объекты по области.

## 3. Архитектура

Пайплайн линейный, без оркестратора. **Три этапа: сбор → парсинг → анализ.** Этапы связаны
только через файлы: скрипт анализа не знает, как получены данные, а скрипт сбора — что с ними
будет дальше. Поэтому любой этап перезапускается отдельно, а повторный запуск использует кэш.

```
scripts/
  steps/            ← общий слой: скачать и разобрать (нужен всем сферам)
  overview.py       ← ОБЩАЯ СВОДКА
  finance.py        ← ФИНАНСОВЫЙ СЕКТОР
  labor.py          ← РЫНОК ТРУДА
  goods.py          ← РЫНОК ТОВАРОВ И УСЛУГ
  make_presentation.py
```

Почему сбор общий, а аналитика раздельная: выгрузка OSM (739 МБ) и сборник Росстата нужны сразу
нескольким сферам — банки и магазины лежат в одном файле OSM, разделы статистики в одном архиве.
Поэтому скачивание и разбор выполняются один раз, а аналитика у каждой сферы своя.

### Слой сбора и парсинга (`scripts/steps/`)

| Скрипт | Что делает | Вход → выход |
|---|---|---|
| `download_rosstat.py` | скачивает сборник | сайт Росстата → `data/rosstat/Region_Pokaz_2025.rar/.pdf` |

| `download_osm_pbf.py` | выгрузка Приволжского ФО | Geofabrik → `*.osm.pbf`, 739 МБ |
| `parse_osm_objects.py` | потоковый разбор PBF, отбор по тегам, фильтр по границе | PBF → `objects.csv/.json`, 2 432 |

## 4. Как собраны данные

### 4.1 Росстат: от архива до выборки

Три шага. Первый — скачать архив (11 МБ) и PDF сборника. Архив содержит 22 раздела в формате
.docx. Второй шаг — перевести каждый раздел в текст: скрипт обходит **XML-тело документа**,
чтобы сохранить порядок абзацев и таблиц (стандартные `doc.paragraphs` и `doc.tables` этот порядок
теряют). Результат — 23 текстовых дампа, 823 таблицы.

Третий шаг — отобрать таблицы со строкой «Саратовская область». Здесь две особенности вёрстки:

1. **Части одной таблицы идут отдельными блоками без подписи.** Номер таблицы наследуется
   от последней встреченной подписи («Продолжение табл. 20.10» или «20.10. НАЗВАНИЕ»).
2. **В «продолжениях» название региона стоит в последней ячейке, а не в первой.** Поэтому
   регион ищется в любой ячейке строки. Если искать только по первой — теряется 79 таблиц
   из 476, и вместе с ними, например, вклады за 2025 год.

Для каждой найденной таблицы сохраняются: номер таблицы, шапка (годы и подписи столбцов) и строки
региона. Это ключ к следующему шагу: числа потом **читаются** из этой выборки, а не переписываются
в код.

### 4.2 Вакансии: обход лимита API

Портал отдаёт 7 939 активных вакансий по региону, но накладывает ограничение
`offset + limit ≤ 200` на запрос (фильтры по датам отвечают HTTP 500), поэтому полный перебор
одним циклом невозможен.

**Решение:** выборка строится по **129 ключевым словам профессий**, по две страницы на слово,
в 5 потоков. Результаты складываются в словарь по `id` вакансии — дедупликация получается
автоматически, так как ключ уникален. Сетевые сбои обрабатываются тремя попытками с растущей
паузой; неудача одного слова не рвёт сбор.

**Собрано:** 4 183 уникальные вакансии — 52,7% активных. 1 613 профессий (с учётом регистра
написания — 1 760), 1 119 работодателей.

**Поля (15):** id, профессия, зарплата от, зарплата до, работодатель, ИНН, город, широта, долгота,
дата публикации, сфера деятельности, требуемый опыт, образование, характер работы, график.

**Полнота:** город — 100%, зарплата — 99,8% (у 8 вакансий в поле ноль, считается как «не указано»),
координаты — 96,1%.

### 4.3 OpenStreetMap: объекты экономики

Выгрузка Приволжского федерального округа с Geofabrik — 739 МБ. Причина замены: Overpass API
сначала отдавал 406 при браузерном User-Agent, затем не выдерживал запрос по области (таймаут
912 с), а после серии запросов заблокировал IP. Локальная выгрузка снимает зависимость от чужого
сервиса и даёт все объекты региона, а не только попавшие в ответ.

**Разбор потоковый** (`osmium.SimpleHandler`, `locations=True`): файл не загружается в память,
обработчик получает объекты по одному. Пройдено **112 332 492 узла** и **11 245 237 линий**.

**Отбор по тегам** (теги взяты из образца, чтобы регионы сравнивались на одной методике):

| Категория | Теги |
|---|---|
| Банки, банкоматы | `amenity = bank`, `amenity = atm` |
| Производства | `industrial = *` |
| Магазины | `shop = supermarket`, `convenience`, `general` |
| Услуги | `shop = beauty`, `hairdresser`, `massage`; `leisure = tanning_salon` |

Отобрано 47 658 объектов-кандидатов. Точки (`node`) берутся как есть, площадки (`way`) — по центру
масс их вершин. После фильтра по границе области остаётся **2 432 объекта**.

### 4.4 Геометрия: контур и точка внутри полигона

Прямоугольник вокруг области захватывает пять соседних регионов и часть Казахстана, поэтому
фильтрация идёт по реальному контуру, полученному из Nominatim (8 307 точек).

Проверка «точка внутри полигона» — лучевой метод: из точки пускается горизонтальный луч, и если
он пересекает контур нечётное число раз, точка внутри. Цикл на Python занял бы часы
(47 658 × 8 307 = ~396 млн сравнений), поэтому проверка **векторизована через numpy**: строится
матрица «точка × ребро», условие пересечения считается сразу для всех точек. Чтобы не съесть
память, обработка идёт **порциями по 800 точек** — полная матрица заняла бы около 3 ГБ.

**Привязка к городам.** В OSM поле города заполнено редко, поэтому город определяется
по ближайшему из 27 населённых пунктов области. Расстояние — равноугольная аппроксимация
(111 км на градус с поправкой на косинус широты); сравниваются квадраты расстояний, корень
берётся один раз. Если ближайший город дальше 30 км, объект попадает в группу «прочие
населённые пункты». В пределах 30 км оказалось 96% объектов. Указанный в OSM город имеет
приоритет над расчётным.

## 5. Что посчитано

Все числа Росстата читаются из выборки по адресу «номер таблицы + год + подпись столбца»:

```python
dep = rv.require(t, "20.10", year=2025, label="физических", part=1)   # 514 711
```

Если столбец не найден, скрипт падает с ошибкой — пустое значение не подставляется,
и в презентацию не может попасть цифра неизвестного происхождения.

### 5.2 Структура экономики

Секторы — не готовый показатель сборника, а агрегация видов деятельности: первичный = сельское
хозяйство + добыча; вторичный = обработка + энергетика + водоснабжение + строительство;
третичный = остаток.

| Разрез | Первичный | Вторичный | Третичный |
|---|---|---|---|
| ВРП, 2023 | 17,6% | 28,3% | 54,1% |
| Занятость, 2024 | 8,6% | 24,8% | 66,6% |

Вывод: в первичном секторе доля в ВРП вдвое больше доли в занятости — производительность там
выше средней.

**Формы собственности:** частный сектор — 81,6% организаций и 79,9% оборота; государство
и муниципалитеты — 12,9% организаций и 3,6% оборота.

| Магазины | 1 576 | магазин у дома 951 (60,3%), супермаркет 621 (39,4%), general 4 |
| Услуги | 268 | парикмахерские, салоны красоты, массаж |
| Производства | 41 | factory 12, oil 10, gas 9, warehouse 3, cement 2 |

Торговые сети: Магнит 122, Пятёрочка 94, Гроздь 22; всего 33 сети, но бренд указан лишь
у 20,7% магазинов. Территории: Саратов 818, Балаково 263, Энгельс 169, прочие 635 — на три
крупнейших города приходится 63,5% магазинов. Нефть и газ — 46% размеченных производств;
адрес улицы указан только у 18,9% объектов.

**Главное противоречие работы:** по объектам OSM магазинов в 38 раз больше, чем производств
(1 576 против 41), а по деньгам промышленность больше розницы в 1,6 раза (1 039,3 против 648,5).
Это не ошибка, а свойство источника: розничные точки размечены хорошо, промышленные площадки —
плохо. **OSM описывает размещение, Росстат — масштаб; смешивать их в одном показателе нельзя.**

## 7. Ограничения

1. **Выборка вакансий — 52,7%** активных (следствие лимита API), смещена в сторону профессий
   из списка ключевых слов. Выводы формулируются как «в выборке», а не «в регионе».
2. **OpenStreetMap — краудсорсинговые данные:** розница размечена хорошо, промышленные площадки —
   плохо; полнота в сельской местности ниже, чем в городах; улица указана у 18,9% объектов.
3. **Показатели в текущих ценах**, без дефляции: рост вкладов и ВРП частично инфляционный.
4. **Филиалы ≠ отделения:** таблица 20.9 считает филиалы, а не дополнительные офисы и кассы.
5. **Доля Сбербанка** сопоставляет его рублёвые вклады (данные банка) со всеми вкладами населения
   (данные Банка России) — два разных источника.
6. **ВРП публикуется с лагом в один год:** последние данные — за 2023 г. Инвестиции — 2024 г.,
   то есть отношение «инвестиции к ВРП» сравнивает разные годы.
7. **Связи (relations) в OSM не разбираются:** часть промышленных площадок нанесена
   мультиполигонами, поэтому по производствам 41 объект против 50 у Overpass.
8. **Справочник подразделений Банка России** снят с публикации (404), поэтому институциональная
   статистика взята из сборника, а физическое присутствие банков — из OSM.

## 8. Воспроизводимость

```bash
pip install -r requirements.txt

# 1. Сбор данных (один раз)
python scripts/steps/download_rosstat.py
python scripts/steps/get_region_boundary.py
python scripts/steps/download_osm_pbf.py
python scripts/steps/parse_vacancies_trudvsem.py
python scripts/steps/rosstat_docx_to_text.py
python scripts/steps/rosstat_extract_region.py
python scripts/steps/parse_osm_objects.py
python scripts/steps/assign_cities.py

# 2. Аналитика по сферам
python scripts/overview.py
python scripts/finance.py
python scripts/labor.py
python scripts/goods.py

# 3. Презентация (вне пайплайна)
python scripts/make_presentation.py
```

**Зависимости:** `numpy`, `python-docx`, `python-pptx`, `osmium` — ставятся из `requirements.txt`
либо из локальной папки `.tools`.

**Время:** разбор PBF — около 30 минут (однократно, результат кэшируется), сбор вакансий — около
5 минут, обработка сборника — около 2 минут, аналитика и сборка презентации — секунды.

**Идемпотентность:** повторный запуск использует уже скачанные файлы; проверяется не только
существование файла, но и его размер, чтобы обрывок скачивания не считался готовым результатом.

**Пути** вычисляются от расположения скриптов, поэтому проект работает из любой папки.
Шаблон СПбГУ лежит вне репозитория, путь задаётся переменной окружения `SPBU_TEMPLATE`.

## 10. Что не сделано и куда развивать

- **Карта объектов** по координатам и тепловая карта зарплат — координаты есть у 96% вакансий
  и у всех объектов, но визуализация не построена.
- **Второй источник вакансий** — не подключён (HeadHunter требует OAuth); тематические
  телеграм-каналы и отчёты торговых сетей записаны как кандидаты.
- **Оркестратор и автотесты** — пайплайн запускается вручную; этапы связаны через файлы,
  поэтому оркестратор добавляется надстройкой без правок скриптов.
- **Дефляция рядов** — денежные показатели в текущих ценах.
- **Снятие смещения выборки вакансий** — нужен другой способ обхода лимита API.
- **Разбор relations в OSM** — добавит часть промышленных площадок.
- **Каталог данных** — карточки по каждому набору (источник, лицензия, схема, ограничения)
  пока в виде журнала `data/README.md`.

## 11. Короткие ответы на частые вопросы

- **Почему 4 кредитные организации — это мало?** Это юрлица, зарегистрированные в регионе;
  присутствие банков из других субъектов — это филиалы и доп. офисы, физически 547 объектов OSM.
- **Вклады выросли в 6 раз — это инфляция?** Ряд в текущих ценах, это ограничение; для сравнения
  нужна дефляция.
- **Почему 4 183 вакансии из 7 939?** Лимит API в 200 записей на запрос; выборка по ключевым
  словам, охват 52,7%.
- **Почему средняя 45 349, а медиана 38 000?** Правый хвост: 130 вакансий дороже 100 тысяч.
- **Почему вакансии дают 38 000, а Росстат 58 626?** Разные величины: предлагаемая в объявлениях
  против начисленной по всем работникам.
- **Почему производств 41, а магазинов 1 576?** Свойство OSM: розница размечена хорошо,
  промплощадки — плохо. По деньгам соотношение обратное.
- **Как из сборника получаются числа?** Модуль `rosstat_values` ищет таблицу по номеру, столбец —
  по строке годов и подписи, значение берёт из строки региона; если не нашёл — падает с ошибкой.
- **Почему 476 таблиц, а не 823?** 823 — все таблицы сборника, 476 — те, где есть строка
  Саратовской области.
- **Можно ли воспроизвести?** Да: скрипты в `scripts/`, порядок запуска выше, данные кэшируются.
